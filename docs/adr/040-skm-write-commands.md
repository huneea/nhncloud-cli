# ADR-040: Secure Key Manager 쓰기: 키 저장소는 ID로 지정하고 삭제 예약과 즉시 삭제를 명령으로 나눈다

- **status**: `accepted`
- **결정**: SKM API v1.3의 키·키 저장소·인증 정보 생성, 수정, 삭제와 기밀 데이터 값 수정을 지원한다. [ADR-039](039-skm-client-auth-and-secret-output.md)의 "생성·수정·삭제는 범위 밖" 결정을 이 ADR이 대체한다.
  - 키 생성과 인증 정보 API는 키 저장소를 이름(`keyStoreName`)으로 받는다. CLI는 조회 명령과 같이 `<keystore-id>`를 받고 상세 조회로 이름을 얻어 보낸다.
  - 삭제 예약(7일 뒤 삭제)은 `delete`, 예약된 대상의 즉시 삭제는 `purge` 명령이다. 키, 키 저장소 삭제(비활성화), 인증 정보의 모든 삭제 명령은 `--yes`가 없으면 API 요청 전에 종료 코드 3으로 끝난다.
  - 키 저장소 수정 API는 전체 교체다. CLI는 주지 않은 이름·설명·인증 사용 여부를 현재 값으로 채운다. 조회 응답에 `authMode`가 없어 `--auth-mode`는 매번 필수다.
  - 대칭키·비대칭키 생성의 `autoRotationPeriod`는 항상 0(자동 회전 안 함)을 보낸다.
  - 기밀 데이터 값과 인증서 비밀번호는 `--value`·`--password` 같은 인수, 파일, 표준 입력으로 받는다. 기밀 데이터 수정 응답에 실린 값은 출력하지 않는다.
- **맥락**:
  - 키 생성·인증 정보 API의 키 저장소 지정 방식(이름)이 조회 API(ID)와 다르다. 명령마다 지정 방식이 달라지면 조회 결과를 다음 명령에 바로 넘길 수 없다.
  - 즉시 삭제는 삭제 예약 상태인 대상만 받는다. 예약은 7일 안에 콘솔에서 되돌릴 수 있지만 즉시 삭제는 되돌릴 수 없다. 옵션 하나로 둘을 가르면 플래그를 붙이는 실수 한 번으로 복구 불가능한 쪽이 실행된다.
  - 키 저장소 상세 조회 응답에는 `authMode`가 없다. 현재 값을 읽어 채우는 방식으로는 이 값을 보존할 수 없다.
  - 공식 문서는 `autoRotationPeriod`의 단위를 밝히지 않는다.
  - 공식 문서: [API v1.3 가이드](https://docs.nhncloud.com/ko/Security/Secure%20Key%20Manager/ko/api-guide-v1.3/), [공공기관용 API v1.3 가이드](https://docs.gov-nhncloud.com/ko/Security/Secure%20Key%20Manager/ko/api-guide-v1.3-gov/). 키 저장소 수정·삭제는 `body: null`로 응답한다.
- **대안 기각**:
  - `--keystore-name`으로 이름을 직접 받기: API 호출이 하나 줄지만 조회 명령과 지정 방식이 달라진다.
  - `delete --now`로 즉시 삭제: 명령은 하나로 줄지만 위 맥락의 실수 위험이 남는다.
  - 키 저장소 수정에서 모든 값을 필수로 받기: 단순하지만 설명 하나를 바꿀 때도 인증 설정 전체를 다시 입력해야 한다.
  - 자동 회전 주기를 옵션으로 노출: 단위를 모른 채 도움말을 쓰게 된다. 실측으로 단위를 확인한 뒤 추가한다.
- **결과**:
  - 얻는 것: 키 저장소 생성부터 키 생성, 인증 정보 등록까지 CLI로 끝낼 수 있다. 조회 명령의 출력을 쓰기 명령 인수로 그대로 쓴다.
  - 감당할 것: 키 생성과 인증 정보 명령은 이름 조회 요청을 한 번 더 보낸다. 키 저장소 수정은 읽은 뒤 쓰는 사이에 다른 변경이 들어오면 그 변경을 덮는다. 자동 회전을 쓰는 키는 콘솔에서 설정한다.
- **적용 범위**: SKM 쓰기 명령에 한정한다. 출력 마스킹과 클라이언트 인증 범위는 ADR-039를 따른다.
